# Domain docs

本文件规定工程技能在探索代码库时如何读取 ChoiceMind 的领域文档。

## 开始探索前

依次检查：

- 根目录的 `CONTEXT.md`；
- 根目录的 `docs/adr/`，并读取与当前工作区域有关的 ADR。

如果这些文件尚不存在，继续当前工作，不需要提前报告缺失或主动创建。领域术语或架构决策真正形成时，再通过 `domain-modeling` 等流程按需创建。

## 文件布局

当前仓库采用单上下文布局：

```text
/
├── CONTEXT.md
├── docs/
│   └── adr/
│       ├── 0001-example-decision.md
│       └── 0002-example-decision.md
└── src/
```

`CONTEXT.md` 用于维护领域术语、定义、边界及明确避免使用的同义词。

`docs/adr/` 用于记录影响系统结构、接口、依赖或长期演进方式的架构决策。

## 使用领域词汇

在 Issue 标题、规格、重构方案、假设和测试名称中，应采用 `CONTEXT.md` 定义的领域术语，不应随意换用其明确排除的同义词。

如果所需概念尚未出现在术语表中，应先判断：

- 当前表述是否引入了项目并不存在的新概念；
- 或领域模型是否确实存在需要记录的空缺。

只有确认属于真实领域空缺时，才进入领域建模流程。

## 处理 ADR 冲突

如果计划或实现与现有 ADR 冲突，必须明确指出冲突，不得静默覆盖原有决策。例如：

> 与 ADR-0007 的既有决策冲突；建议重新讨论，因为……
